In-depth guide

What the OCR engine does

Optical character recognition looks for shapes in an image that match letters, numbers and punctuation, then assembles them into words. This tool uses a Tesseract.js engine loaded locally alongside the page, together with English language data that helps the recogniser choose between similar possibilities. The image is decoded into pixels in your browser before recognition starts. A progress indicator reports the loading and recognition stages, so you can see whether the engine is preparing, working or finished. When it stops, the panel contains the real text that the engine found, ready for review rather than a prewritten placeholder. The recogniser returns a plain text block rather than a formatted document, so line breaks, columns and table structure may need cleanup in your own editor afterwards.

Where your image goes

Privacy is straightforward here: the picture stays in your browser. Recognition runs in a worker, which is a separate script thread that keeps the page responsive while it processes pixels. The worker and its WASM support files have to be downloaded with the page, just as any other engine asset would be. That download is not an upload of your document. No photo, screenshot or scan is posted to a server by this tool. Once you close or refresh the page, the in-memory image is gone. You still control what happens next, because the extracted text is only copied or downloaded when you choose to do so. If you close the tab during a run, the session ends and you will need to choose the image and start again.

What changes accuracy

Recognition quality depends heavily on the source image. A large, sharp picture with dark printed letters on a plain light background usually gives clean results. Small fonts, fuzzy focus, glare, shadows, low contrast and decorative typefaces can turn one character into another or split words incorrectly. Angled pages are harder than flat ones, and dense tables may be read in the wrong order. Language is a hard limit as well: this build loads English data only, so other scripts are not reliably supported. Handwriting and stylised lettering remain difficult for OCR generally. A few minutes spent preparing a clearer image often improves the result more than repeated recognition attempts. Cropping tightly around the text and resizing a small scan to a clearer size are simple ways to reduce those errors before another attempt.

Reading the result critically

OCR produces text, not a guarantee. The panel may include every word correctly, or it may swap similar letters, add stray spaces, miss punctuation or join two lines together. Treat the result as a draft that you inspect against the original picture. Pay particular attention to proper names, numbers, dates, amounts and links, since a single mistaken character can change their meaning. When the text looks right, use the copy button to paste it elsewhere or download it as a plain .txt file. That file contains only the extracted text, which makes it convenient for notes, spreadsheets, accessibility checks and search indexes after you have made any needed corrections. The download keeps the spelling exactly as recognised, so make corrections in your own document if you plan to publish or share the content widely.

Troubleshooting common failures

If the engine never reaches recognition, check that the worker and WASM files loaded with the page. Network filtering, an interrupted refresh or offline use can prevent them from arriving, and reloading usually fixes the problem. If recognition runs but returns little or nothing, inspect the image: crop away clutter, straighten the page, increase contrast or use a sharper source. Very large images can be slow to decode, so a moderate resized copy may work better. Remember that English-only language data cannot solve a page written in another language. After any retry, compare the new output with the original instead of assuming that a longer result is automatically a more accurate one. A second try with a better crop is usually faster than manually fixing dozens of uncertain characters in the output.

Frequently asked questions

Does my image get uploaded for recognition?

No. The image is decoded in your browser and passed to a locally loaded Tesseract.js worker. The page must download the worker and WASM files with its other assets, but your image bytes are not sent to LetitEdit or an outside OCR service.

Why is this build English only?

It loads English language data, so it recognises printed English characters and words. Other scripts and languages are outside this build and may produce poor or empty results even when the image itself is clear.

What affects recognition accuracy?

Font, size, contrast and language all matter. Sharp, evenly lit images with generous spacing usually work best, while blur, glare, low contrast, decorative fonts and angled text increase mistakes. Handwriting is unreliable.

Why did the worker fail to start?

The OCR engine needs its worker and WASM download with the page. If those files are blocked, cached incorrectly or unavailable offline, recognition cannot begin. Reload the page, allow the files to load, then try again.

Can I trust the text without checking it?

Always review it. The output shown is genuinely extracted text with copy and .txt download controls, but OCR can confuse similar characters, spacing and punctuation. Compare important names, numbers and links with the original image before using them.
