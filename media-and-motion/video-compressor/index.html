Guide

What video compression does

A video file stores far more information than the eye notices frame by frame. Compression decides which detail can be simplified or discarded while the clip still looks close to the original. Reducing the bitrate asks the encoder to spend fewer bits on each second. Reducing the resolution rebuilds each frame with fewer pixels. Both approaches make the file smaller, and both require a real decode and re-encode.

This tool never renames a file or changes its extension and calls it compressed. It decodes the actual frames, optionally resizes them, encodes a new video track, encodes the audio again when you keep it, and muxes both into a new container. The result panel compares the measured input and output sizes.

How to compress a video in your browser

  1. Add one video. Drag a file onto the upload area or choose Browse video. MP4, M4V, MOV, WebM and MKV are accepted when this browser can decode them.
  2. Read the source details. The workspace shows the duration, original resolution, frame rate, codecs, rotation, file size and source bitrate so you know what you are starting from.
  3. Choose a compression mode. High Quality protects detail, Balanced is the recommended default, and Smallest File compresses harder. Advanced exposes every supported control.
  4. Set the output. Keep the original resolution or choose 4K, 1440p, 1080p, 720p, 480p, 360p or exact custom dimensions. Smaller frames need less data.
  5. Adjust advanced options if needed. Choose a target bitrate or target file size, enable CRF, cap the frame rate, pick the container codec, and keep or remove audio.
  6. Compress and wait for real progress. The worker reports the video, audio and finalizing stages. You can cancel safely while it runs.
  7. Check the measured result. Compare before and after, read the saved bytes and percentage, preview the compressed video, then download it.

Compression modes explained

  • High Quality uses a higher bitrate and a larger share of the source bitrate. It applies moderate compression and is the safest choice when the picture matters more than storage.
  • Balanced is the default. It lowers the video bitrate noticeably while keeping a practical level of detail, and it uses a moderate audio bitrate.
  • Smallest File uses the strongest compression and the lowest audio bitrate. It is useful for sharing, previews and archives, but fine texture and fast motion may become softer.
  • Advanced replaces the preset targets with values you supply. The plan panel updates to show the bitrate the encoder will receive.

The modes are not fixed file-size promises. Each mode calculates a video bitrate from the output pixel count, the effective frame rate and the source bitrate, so a 4K clip and a 360p clip receive different targets even in the same mode.

What the advanced settings control

Target bitrate sets the video data per second. Higher values keep more detail. Target file size converts the size you enter into a video bitrate using the clip duration, audio bitrate and container overhead. It is a goal: complex scenes and encoder behaviour can push the real size above or below it.

Constant quality (CRF) asks the encoder for a consistent visual quality rather than a fixed bitrate. Lower values produce larger, more detailed files. Browser encoders differ in support; the tool always supplies a bitrate fallback and the plan panel explains which target is active.

Maximum frame rate caps the encoded frame rate. If you choose 30 fps for a 60 fps source, every other frame can be dropped and the previous frame is extended, which saves data without changing duration or audio sync. The tool never invents duplicate frames to raise the rate.

Resolution changes the encoded frame size. Aspect ratio is preserved, so the picture is never stretched. A custom size with the aspect lock off is letterboxed inside the chosen frame rather than distorted.

Audio can be kept at 64–256 kbps or removed entirely. MP4 uses AAC audio and WebM uses Opus audio. Audio is normalized to 48 kHz stereo and keeps its timing.

Supported formats, codecs and limits

MP4, M4V, MOV, WebM and MKV inputs are accepted when the browser can decode their video and audio codecs. H.264/AAC MP4, VP8/VP9/Opus WebM and many MOV, M4V and MKV files work in current Chrome and Edge. Firefox and Safari expose different decoder and encoder sets, so the same file may work in one browser and not another.

AVI is not decoded by the browser engine used here, so AVI files are rejected with an explanation rather than a broken result. Convert AVI to MP4 or WebM first if you need to compress it.

Output is limited to formats this browser can genuinely encode at the chosen resolution. MP4 uses H.264 video with AAC audio. WebM uses VP9 or VP8 video with Opus audio. If a codec cannot be encoded at the selected size, its option is disabled instead of producing an invalid file. Output is capped at 4096 pixels per edge and dimensions are rounded to even numbers for the encoder.

Reading your compression results

The result panel uses measured numbers, not estimates. Size saved is the original size minus the compressed size. Compression percentage is the saved bytes divided by the original size, multiplied by 100. A positive percentage means the new file is smaller.

Re-encoding can also increase a file. A clip that was already encoded at a very low bitrate may need more data to survive another generation, or the container may add overhead. When that happens the page reports the increase plainly and does not claim a saving. In that case, try Smallest File, a lower resolution, a frame-rate cap or removing audio.

Before compression, only real inputs are shown: the source size, the output resolution, the selected codecs and the encoder targets. The tool does not invent a quality score. The actual output size is known only after the file has been written and measured.

Common reasons to compress a video

  • Upload limits. Email, forms, learning platforms and chat apps often cap attachment size.
  • Faster sharing. Smaller files move through messaging and cloud storage with less waiting.
  • Storage and archives. A lower bitrate or resolution keeps a long recording manageable.
  • Web playback. Lighter files start faster and use less bandwidth on mobile connections.
  • Presentations and embeds. A 720p or 1080p version is usually enough for a slide or website player.
  • Slow devices. A 480p or 360p export plays more reliably on older hardware.

Privacy, speed and memory

The video is decoded, compressed and muxed inside a Web Worker in this tab using Mediabunny and the browser's WebCodecs implementation. The worker is loaded only after you add a video and is terminated when you remove the video or leave the page. Source and result object URLs are released when you replace the video, start another job or navigate away.

Compression speed depends on the clip length, resolution, frame rate and the device's encoder. 4K and long videos need more memory and time. The page warns when the input file is large, the clip is long or the output is very large. If a job fails, try a shorter clip, a smaller resolution, a lower frame-rate cap or closing other memory-heavy tabs.

There is no upload, account, paid API or server-side copy. The only network requests are for the page, its stylesheet and the self-hosted engine and worker files.

Troubleshooting

  • The file is rejected. The browser may not decode its codecs, it may be corrupted or audio-only, or it may be an AVI. Try an MP4 or WebM that plays in the same browser.
  • A format or codec is disabled. The browser cannot encode it at the chosen size. Try the other format or a smaller resolution.
  • The output is larger than the source. The source was already heavily compressed. Use Smallest File, a lower resolution, a frame-rate cap or a lower custom bitrate.
  • The compression is slow. Long or high-resolution clips take longer. Keep the tab open and avoid heavy background tabs.
  • It runs out of memory. Try a shorter clip or a smaller output, especially on phones.
  • The preview will not play. The browser may lack the playback codec even when the encoder can produce the file. Download it and open it in a video app.
  • Audio is missing. Check that Keep the audio track is enabled and that the source actually has audio. A silent source exports without an audio track.

Frequently asked questions

Does this video compressor upload my video?

No. The video is decoded and re-encoded inside your browser tab with WebCodecs and Mediabunny. It is not sent to LetitEdit or to a third-party service, and no account is required.

Which formats can I compress?

MP4, M4V, MOV, WebM and MKV are accepted when this browser can decode their video and audio codecs. AVI is not decoded by the browser engine, so AVI must be converted to one of those formats first. Corrupted, oversized and audio-only files are rejected with a clear message.

Is the compressed video really smaller?

The tool measures the original and the exported file and shows the real sizes. Balanced and Smallest File usually reduce size, but a file that is already heavily compressed can grow when it is re-encoded. When that happens the result panel says so instead of claiming a saving.

What is the difference between the three modes?

High Quality keeps more detail and uses a higher bitrate. Balanced is the recommended default and aims for a practical size. Smallest File uses stronger compression and lower audio bitrates, so the picture may lose detail. Advanced lets you set the bitrate, target size, CRF, frame rate, resolution and audio yourself.

Does the compressor guarantee a target file size?

No. A target size is converted into a video bitrate for the clip duration and is treated as a goal. The final size depends on scene complexity, the encoder, the container and the audio. The actual size is measured after export.

Will compressing change the duration or audio sync?

No. The tool keeps the source duration, preserves frame timestamps and normalizes audio to 48 kHz stereo at the same timing. If you choose a maximum frame rate, extra frames are dropped and the previous frame is extended, so audio stays aligned.

What is CRF or constant quality?

Constant quality targets a visual quality level instead of a fixed bitrate. Lower values keep more detail and produce larger files. Browser encoders vary in support, so the tool also supplies a bitrate fallback and says when the fallback is used.

Can I remove the audio to make the file smaller?

Yes. Choose Remove audio in the advanced settings. The exported file then has no audio track. Leaving audio enabled preserves it and lets you pick an audio bitrate from 64 to 256 kbps.

Will compressing improve the quality?

No. Compression removes data to make the file smaller, so quality can stay close to the source but cannot improve. Upscaling the resolution also cannot add real detail. Keep the original resolution and a high bitrate when quality matters most.

Why is an output format or codec disabled?

The tool asks the browser which codecs it can actually encode at the chosen resolution. A format or codec that is unavailable is disabled with an explanation instead of producing a broken file.
