Guide

What makes this a real video editor

A browser video editor is only honest if the picture you arrange is the picture that leaves the machine. This workspace keeps one compositor for both jobs: the preview canvas and the export worker call the same drawing code with the same project data. Trimming, layer order, text shaping, filters, transitions, crops, keyframes and subtitles therefore travel into the encoded file instead of existing only as interface decoration.

The timeline is the source of truth. Clips have a start, a duration and source in and out points. Trimming changes how much of the source is used; moving changes when it appears; splitting produces two clips that share one source file without re-encoding it. Layers are tracks: the top track in the list is drawn last and therefore appears in front.

How to edit a video in the browser

  1. Import your media. Choose video, images and audio from your device, or drop them onto the page. Thumbnails and measured metadata appear in the Media tab.
  2. Place clips. Tap Add to put a file at the playhead, or drag a card onto a compatible track. A new track is created when the existing ones are full.
  3. Arrange and trim. Drag clip bodies to change timing, drag either edge to trim, and press Split to cut at the playhead. Snapping lines clips up with neighbours, the playhead and zero.
  4. Build layers. Add text, shapes, backgrounds, logos or stickers on their own tracks. Use the layer controls in the properties panel to bring a clip forward, send it backward, or move it to the front or back.
  5. Style and animate. Apply a transition at the start of a clip, a filter and colour grade, an entrance or exit animation, or keyframes for position, scale, rotation and opacity.
  6. Mix audio. Set clip gain, fades and mute, then balance tracks and the master volume. Audio is mixed from every audible clip at export time.
  7. Export. Choose MP4 or WebM, resolution, aspect and quality, then watch real progress. The finished file is read back and its measured metadata is shown before you download it.

Tracks, clips and layer stacking

Clips on one track cannot overlap in time; the editor refuses a move that would collide and explains why. That constraint is what makes the stacking model predictable. Moving a clip up a track brings it forward in the composition; moving it down sends it backward. Bring to Front and Send to Back move it to the extreme video layer. If the neighbouring track is occupied at that moment, the editor gives the clip its own layer rather than silently dropping other clips.

Horizontal position is always timing, never stacking. A clip that starts later does not move in front of an earlier one. This is the same distinction professional timelines make, and it is why the layer controls can describe a single vertical order while the timeline describes time.

Transitions, filters and colour correction

There are 56 named transitions in six categories: basic blends, slide and push, wipe and reveal, zoom, motion and stylised effects. A transition is attached to the incoming clip and blends its first seconds with the moving tail of the previous clip on the same track. Duration is limited by both clips, the direction can be reversed, and choosing None removes it. Because the blend is drawn by the shared compositor, an exported file contains the same mixed frames.

The 18 filters are complete looks: monochrome, sepia, cool, warm, vintage, noir, fade, vivid, cinematic, dream, infrared, x-ray, poster, sketch, comic, blur, vignette and none. Intensity blends each look with the original. Colour correction is separate and additive: brightness, contrast, saturation, temperature, tint, exposure, highlights, shadows, gamma, sharpness, fade and vignette. A filter replaces the previous look; the correction controls refine whatever is underneath.

Text, titles and subtitles that survive export

Every title, caption, lower third and sticker is an independent layer, not a single shared text box. You can change content, font stack, size, weight, italics, underline, colour, outline, shadow, background, opacity, line spacing, letter spacing, alignment, direction, position, scale and rotation. Text is shaped by the browser's own canvas engine with system font stacks for Latin, Arabic and Urdu, Devanagari and CJK. Right-to-left direction can be forced, and the same shaping call runs during export.

Subtitles are a separate track of timed cues. Type them manually, adjust the in and out points, or import SRT or WebVTT files. Style the whole track once, preview it over the picture and download the cues again as SRT or VTT. This editor does not claim automatic transcription and does not upload audio anywhere.

Audio: music, voiceover and effects

Audio clips live on audio tracks. Trim, split, move, duplicate, replace, mute and fade them like video clips, with a waveform drawn from decoded samples where one is available. Each track has its own volume and mute, and the project has a master volume. On export every audible clip is resampled to a 48 kHz stereo mix, with clip gain and fades applied sample by sample.

Speed changes also change pitch because the same samples are resampled. Pitch-preserving time stretching is not part of this browser-only build, and the interface states that rather than pretending otherwise. Preview audio runs through a Web Audio mixer with clip, track and master gain, so the mix can be checked before export.

Export formats, resolutions and limits

MP4 output uses H.264 video and AAC audio; WebM uses VP9 video and Opus audio. Verified exports include 480p and 1080p landscape, 720p portrait and a square 854×854 WebM, plus custom dimensions that the device encoder accepts; the frame rate follows the project setting. Each frame is composed at the export size, so text and vector shapes are re-rendered sharply rather than upscaled. Quality presets choose a target video bitrate; audio bitrate follows the preset.

The exporter checks that the browser can encode the chosen codec at the chosen size before starting. Progress reports the real frame loop, audio mix and container finalisation, and Cancel stops the worker and leaves no partial download. When the file is finished it is opened again with a media parser, and the displayed duration, size, resolution, codec and bitrate come from that read-back. A duration mismatch aborts the export instead of presenting a broken file.

Project files, autosave and media

The project is plain JSON: canvas settings, tracks, clips, effects, keyframes, layers, subtitles and audio levels. It autosaves to this browser after changes and can be downloaded or opened manually. Original media files are stored separately in IndexedDB when the browser's storage quota allows, under a bounded budget, and are never embedded in the project file. If they are missing after a reload, the editor lists them and relinks the clips when you re-import the originals by name.

Mobile editing at 320 pixels and up

The workspace reflows into one column on phones: preview first, then the timeline, with Tools and Properties available as bottom sheets and a dock for tools, properties, project actions and export. Track headers stay pinned while the timeline scrolls horizontally, trim handles grow for touch, and clip dragging uses pointer events rather than desktop-only drag and drop. Every control keeps a visible label or an accessible name, and the layout is tested at 320, 360, 375, 390 and 430 pixel widths.

Privacy, performance and file limits

Files are read with local file APIs, decoded by the browser's own media engine through Mediabunny, composed on canvas and encoded with WebCodecs. No media, project or frame is uploaded. Object URLs are released when media is removed or the page closes. The heaviest work is kept off the main thread during export, thumbnails are generated as small JPEGs, and decoded frames are cached in resolution buckets so scrubbing does not re-decode every time.

Large projects are limited by device memory and browser storage, not by a server quota. A practical ceiling is a few minutes of 1080p source at a time; 4K sources and long timelines need more memory and export time. Autosaved media is capped so the editor can report when the browser refuses to store another file instead of silently failing.

Troubleshooting

  • A file is rejected. The browser could not decode its codec, or it is larger than the 2 GB per-file guard. Re-encode it with the Video Converter, or use a browser with that decoder.
  • Export is unavailable. The browser does not expose WebCodecs VideoEncoder. Editing still works; use a current Chrome or Edge release to export.
  • Clips look black after opening a project. The original media is not loaded. Import the same files again; the relink banner lists what is missing.
  • A clip will not move. Another clip occupies that span, the track is locked, or the clip itself is locked. Unlock it or make room; nothing is moved silently.
  • The preview stutters. Lower the preview quality. Preview decodes near the playhead on the main thread, while export is deliberately slower and more precise.
  • Arabic or Hindi text shows boxes. The chosen font stack is not installed on this device. Try the dedicated Arabic, Devanagari or CJK stack, or install a font that covers the script.

Frequently asked questions

Does the editor upload anything?

No. Import, decode, preview, composition and export all happen in this browser tab. The page loads only its own stylesheets, the self-hosted Mediabunny engine and the local export worker.

Can I use 4K source files?

Yes, if the device can decode them. Preview uses smaller decode buckets, while export requests frames near the output size. Large 4K projects consume more memory and take longer to encode.

Are transitions and filters baked into the file?

Yes. The export worker calls the same composition function as the preview, so every visible transition, filter, colour adjustment, crop, text style and keyframe is drawn into the encoded frames.

Can I keep working after a reload?

The timeline autosaves locally and offers to restore. Original media files are also kept in browser storage when quota allows; if they were evicted, re-import them by name and the clips relink. Download a project file for a portable copy of the edit.

Does speed editing preserve pitch?

No. Audio is resampled with the video, so pitch changes with speed. Pitch-preserving time stretching is not implemented here, and the speed control says so.

Can I edit with a keyboard only?

Yes for the main operations. Clips are focusable, arrow keys nudge timing in 0.1 second steps, Shift moves one second, and trim handles accept arrow keys. Split, delete, duplicate, undo, redo, play, pause and seeking all have keyboard routes.
