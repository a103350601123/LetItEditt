    How this editor works

    The video is the workspace. Everything else is a layer placed over it at a moment you choose.

    1. Upload a video. It loads as the main video and defines the project length, aspect and frame rate.
    2. Pick a moment. Drag the progress strip, tap a thumbnail or use the arrow keys. The time under the preview is always the edit time.
    3. Choose an action. Add text, a sticker, an image, a second video, music, a filter, a transition, a speed change or a crop. Changes apply at the selected moment.
    4. Adjust the layer. Drag text or graphics directly in the preview, resize with the corner handles, rotate with the top handle, or use the precise controls in the sheet.
    5. Save and export. The project autosaves in this browser. Export renders every layer, effect and audio source into a real MP4 or WebM file.

    Designed for a phone, not shrunk from a desktop

    The preview takes the space it needs, the transport sits directly under it, and every editing control is a bottom sheet that fits the screen. The moment strip shows the video as thumbnails with a single overlay lane, not a wall of tracks. Controls are at least 44 CSS pixels where they matter, and vertical page scrolling keeps working even when a swipe starts over the preview.

    Layers without a track grid

    Each text, image, graphic, video insert or music bed is a layer with a start time and a duration. The Layers panel lists them in stacking order; use the arrow controls to bring a layer forward or send it back. The main video always sits at the back. Overlapping layers are allowed and are composited in order by the same renderer used for export.

    Motion, filters and transitions that are real

    Filters, colour adjustments, crops, opacity, rotation, position, scale, transitions and keyframes are project data, not CSS decoration. The preview and the export worker both call the same composition code, so a frame you approve on screen is the frame that is encoded. Keyframes support linear, ease-in, ease-out and ease-in-out timing and can be added, moved, retimed or deleted.

    Audio and export limits, stated plainly

    Music, voiceover and the main video's sound are mixed at export with clip volume, fades, track and master levels. Preview monitoring uses Web Audio. Speed changes also change pitch; pitch-preserving stretching is not implemented. Export requires WebCodecs encoding, available in current Chrome and Edge; other browsers can still edit but may not encode. Long or high-resolution exports are limited by device memory, and the editor reports a failure rather than pretending a file was created.

    Privacy and storage

    No media is uploaded. The project and its imported files are stored locally in IndexedDB so a reload can restore your work; if the browser refuses or evicts storage, the editor tells you and keeps the project JSON available for download. Object URLs are released when media is removed or the page closes.

    Frequently asked questions

    Is there a watermark or an account?

    No. There is no account, no upload and no watermark. Export runs entirely on your device.

    Can I add more than one video?

    Yes. The first video becomes the main video. Additional videos become picture-in-picture layers that you can move, resize, rotate and place at any moment.

    Why does my phone not offer MP4 export?

    MP4 export needs H.264 encoding through WebCodecs. If the browser does not expose it, the export sheet offers WebM when available and otherwise explains that this browser cannot encode. Editing and saving still work.

    Will my project still be here tomorrow?

    It is stored in this browser's IndexedDB. Clearing site data, using private browsing or a full storage quota can remove it. Download the project file for a portable copy.
