How to use MP4 to GIF

  1. Load a video file that your browser can decode.
  2. Choose the start and end of the short section you want to loop.
  3. Set a frame rate; lower values keep the file smaller.
  4. Set the output width; smaller widths process faster and download quicker.
  5. Preview the loop and adjust the range if the action is cut off.
  6. Download the animated GIF; the original video is unchanged.

In-depth guide

A GIF made from your actual video frames

A reaction GIF works because it shows a real moment, not a description of one. This tool takes a section of a video, decodes its frames in the browser and writes them into an animated GIF locally. You choose the range on a preview, set the frame rate and width, and download the result. Nothing is uploaded, so the source stays on your device and the original file is never altered. The name says MP4 to GIF because that is the most common request, but the practical rule is simpler: if your browser can play the video, it can usually be used here. That includes WebM and other supported formats. The tool reports a failure when decoding is not possible rather than substituting a placeholder animation, so what you download really comes from the file you loaded.

Picking a section that loops well

The quality of a GIF depends far more on the chosen moment than on the settings. Look for a short action with a clear beginning and end: a glance, a jump, a hand movement or a reaction that returns close to its starting pose. Scrub the preview and set the start just before the motion begins, then set the end just after it finishes. If the first and last frames look very different, the loop will visibly snap when it repeats. Play the range once more before exporting, because a frame or two can make a surprising difference. A good GIF is usually only a couple of seconds long. Longer ranges produce bigger files and often include dead time that dilutes the moment you actually wanted to share.

Frame rate, width and file size

Frame rate controls how many still images are stored for each second of motion. Twelve frames per second is a reasonable starting point for a small reaction clip; twenty-four looks smoother but roughly doubles the number of frames and the file size. Width controls how large each frame is. A GIF a few hundred pixels across is often plenty for a chat message or a forum post, and reducing width speeds up both encoding and downloading. The two settings interact: a narrow GIF at a high frame rate can be smaller than a wide one at a low rate. Colour is another factor, because the GIF format uses a limited palette, which can make gradients look banded. If the result seems too heavy, shorten the range first, then lower the frame rate, then reduce the width.

Why GIFs have no sound and odd colours

The GIF format was designed for still and simple animated images, not for full video. It has no audio track, so any sound in the source is ignored; keep the original video if narration or music matters. It also stores a small colour palette per frame, which is why photographic scenes can look slightly posterised, especially in skies and soft shadows. That is a limitation of the format rather than a mistake in the conversion. If colours look worse than the preview, try a shorter range with less varied content, or accept that WebM is the better format for faithful video. Dithering can make gradients appear smoother but increases file size. Judge the exported loop on its intended use: a small, instantly readable animation rarely needs photographic colour accuracy.

Limits, privacy and troubleshooting

Everything happens in your browser, so your video is not uploaded and there is no remote conversion queue. That also means your browser's decoding ability sets the boundary. An unsupported codec will not load, and a very large source can be slow to seek and decode even when only two seconds are used. Keep the tab active while the GIF is built, and close other heavy tabs if the page stalls. If the download looks wrong, check the selected range, then try a lower width and frame rate; extreme settings are the usual cause of failed or oversized animations. Reloading clears the working copy, so download the GIF before you leave. Keep the source video as your master and make a fresh GIF whenever you want a different moment rather than trying to edit the animation afterwards.

Frequently asked questions

Does the video get uploaded?

No. The browser decodes the selected frames and the GIF is assembled locally. Nothing is sent to LetitEdit or to an image service, and reloading the page clears the working copy.

Does this only accept MP4 files?

No. The name reflects the common use case, but any video the browser can decode will work. WebM and other playable formats can be used. If a file will not load, the browser may lack support for its codec.

Why is my GIF so large?

GIF stores each frame as a limited palette image, so size grows quickly with width, frame rate and duration. Lower the frame rate, narrow the width or shorten the range. A few seconds at a modest size is usually enough for a reaction loop.

Where did the sound go?

The GIF format does not carry audio. Only the picture is used. If you need sound, keep the original video or use a video export instead of a GIF.

Why does the loop look choppy?

Choppiness comes from too few frames per second or from a source that was recorded at a low frame rate. Raising the GIF frame rate can smooth motion, but it also increases file size and processing time. Very fast motion may still look uneven.

Can I make a GIF from the whole video?

Technically you can if it is short, but long GIFs become large and slow to build. Choose a compact, self-contained moment. The preview lets you check that the action starts and ends cleanly before you export.
