How to use Image Compressor

  1. Choose a PNG, JPG or WebP file within the stated size limit.
  2. Select the output format and, for JPEG or WebP, set a quality level.
  3. Optionally enter a maximum dimension to scale the longest edge.
  4. Compare the original and resulting byte sizes shown below the preview.
  5. Download the compressed image if the trade-off looks acceptable.

In-depth guide

What re-encoding means

Compression here is a fresh encode, not a magic change to the existing file. The browser decodes your picture into pixels, draws those pixels on a canvas and writes a new file using the format and settings you selected. For JPEG and WebP, quality controls how much fine detail may be discarded; lower values usually make the file smaller and the picture softer. For PNG, the encode is lossless, so the quality control has no effect. Re-encoding always starts from the decoded pixels, which means repeated passes can gradually reduce quality. Keep the original file if you may need to try different settings later.

Quality and format choices

JPEG remains a good choice for everyday photographs because it handles smooth colour transitions efficiently. A moderate quality setting often saves a large amount of space with little visible change at normal viewing size. WebP can produce smaller files than JPEG in many cases and can also carry transparency, making it useful for modern web pages. PNG is best when exact pixels matter, such as icons, crisp text or images with transparent areas, but it can be much larger for photos. Try more than one format if size is critical, then inspect the preview at the size where the image will actually appear.

Using a maximum dimension

The maximum dimension control scales the longest edge while keeping the picture's proportions. If you enter 1600 pixels, a wide landscape photo becomes no wider than 1600 pixels, whereas a tall portrait becomes no taller than that value. This is often more effective than lowering quality alone, because fewer pixels need to be stored in the first place. It is useful for web galleries, email attachments and profile pictures that will never be viewed at full resolution. Choose a value that matches the real display size, then check fine text and edges in the preview. You can leave the control empty when you only want to test format and quality.

Reading the byte comparison

The page shows the original file size and the resulting size so you can judge the trade-off rather than guessing. A large reduction is welcome when details still look acceptable, but the smallest number is not automatically the best result. Some pictures are already compressed, and re-encoding them can produce a file that is slightly larger than the source. Text overlays, sharp edges and fine patterns may show artefacts before the byte count falls much further. If the new file is bigger, try a different output format, a lower quality setting or a smaller maximum dimension. Compare the preview with the original before you download and replace anything.

Limits and privacy

Everything happens locally. Your picture is not uploaded, queued on a server or handed to a separate compression service. That makes the tool convenient for personal photos, client previews and drafts you would rather not share. There is still a practical limit: very large files are rejected with a clear message because decoding them can exhaust browser memory or freeze the page. If you see that message, make a smaller copy first or choose a simpler source file. Do not close the page while a large image is being encoded, and download the result only after the sizes and preview look reasonable. Keeping the original is always wise.

A practical workflow

Start with the original file and decide where the result will be used. For a website hero image, choose WebP or JPEG, set quality around the middle of the range, and enter a maximum dimension that matches the largest layout slot. For an archive copy of a document scan, keep PNG and reduce the dimensions rather than accepting colour changes. After compression, open the downloaded file at normal viewing size and zoom in on text faces and thin lines. If detail is missing, raise the quality or relax the dimension cap instead of repeating the same settings. Once the result looks right, keep the source file untouched so you can revisit it later.

Frequently asked questions

Is my image uploaded for compression?

No. The file is decoded, drawn to a canvas and encoded again in your browser. Nothing is sent to LetitEdit or to an external compression service.

Why does the quality setting not change my PNG?

PNG is lossless, so quality does not apply. The setting affects JPEG and WebP output only. To reduce a PNG, try the maximum dimension control or switch to WebP when that format is acceptable.

Why was my file rejected?

Very large files are refused so the page stays responsive and your browser does not run out of memory. The page states the size limit clearly. Resize or trim the original before choosing it again.

Will a lower quality always produce a smaller file?

Usually for JPEG and WebP, but not always. An image that is already heavily compressed may enlarge slightly when re-encoded, and some detailed pictures resist compression. Compare the two byte sizes shown before downloading.

Which output format should I pick?

JPEG suits photographs where tiny colour changes are acceptable. WebP often gives smaller files and can keep transparency. PNG preserves exact pixels and alpha but may stay large, especially for photos.
