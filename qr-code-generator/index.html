In-depth guide

How the code is made

A QR code stores content as a grid of dark and light modules that a camera can interpret. This generator builds that grid in your browser from the text, URL or image content you provide. You can choose how much error correction to reserve, adjust the overall size and change the module and background colours for a particular design. The preview updates so you can see the pattern before downloading anything. Nothing about your input needs to leave the page for the mathematics to work. The result is an image file containing the code, which you can place in a document, on a screen or on printed material after checking that it scans.

The error-correction trade-off

Error correction is one of the most useful controls in a QR generator. Extra redundancy is added to the code so a scanner can still recover the message if a corner is scratched, a label is slightly obscured or printing is imperfect. The trade-off is capacity: a higher level spends more modules on recovery information and leaves fewer for your content. A short URL can usually tolerate a strong level, while a long paragraph or embedded data may need a lower one. If the code will appear on a clean screen, a modest level is often enough. For packaging, signs or outdoor labels, choose more protection and test the final version.

Image mode and capacity

Image mode is deliberately conservative. Your picture is turned into a data URL, which is a text form of the image bytes, and that text is offered as the QR payload. The tool checks whether the data fits the selected code capacity. If it fits, the image is embedded without an upload. If it does not fit, you get a clear error asking for a hosted public URL rather than a mysterious blank preview. LetitEdit never uploads your private image on your behalf. Supplying a hosted URL means you choose where the picture lives and whether that address is public, which keeps the privacy decision with you.

Choosing a download

PNG is the straightforward choice for web pages, presentations and app screenshots because it is a familiar bitmap format. SVG stores the pattern as shapes, so it remains sharp at any print size and is useful for posters, labels and vinyl cutters. Custom colours can make a code fit a brand palette, but the contrast between modules and background must stay strong. Very light yellows, pale greys or similar tones can confuse cameras. Leave clear space around the pattern when you place it, and avoid stretching the exported file unevenly. Before printing many copies, scan a sample with more than one phone to catch display and camera differences.

Privacy and practical checks

Every part of generation happens in the browser, including encoding, customisation and download. A QR code is only a picture of the content you enter, so anyone who scans it will see that content. Do not encode private notes, passwords or confidential links just because generation is local. For plain text and URLs, check that the spelling and destination are correct before exporting. For image mode, remember that a hosted public URL must remain available for as long as the code is useful. Scan the final PNG or SVG in the size and colours you intend to publish, especially before printing, because a code that looks fine on screen can fail when reproduced poorly.

Common mistakes to avoid

Most scanning failures come from presentation rather than encoding. A code printed too small for the camera to resolve, placed on a busy background, or surrounded by a cropped edge is harder to read than one with generous quiet space. Inverted colours can work in specialist software but often fail in ordinary camera apps, so keep dark modules on a light field unless you have tested the reverse. Short links are easier to fit and usually scan faster than long tracking URLs with many query parameters. If you need to change the destination later, remember that a printed code cannot be edited; consider linking to a stable page that you control instead of a temporary campaign address.

Frequently asked questions

Does LetitEdit upload my private image?

No. Image mode converts your picture to a data URL and embeds that text only if it fits the code. If it does not fit, the tool shows a clear error and asks you to supply a hosted public URL. LetitEdit never uploads the private image.

Why was my image rejected in image mode?

A QR code has limited capacity. An embedded data URL can exceed that limit, especially for a large or detailed picture. When this happens, the page explains the problem and asks for a public hosted URL instead; it will not silently shrink or upload your file.

What do error-correction levels change?

Higher levels let a scanner recover data when part of the code is dirty, damaged or covered, but they leave less room for the actual content. Lower levels store more data and are suitable when the printed code will stay clean and unobstructed.

Should I download PNG or SVG?

PNG is a bitmap that suits screens and simple printing. SVG keeps the modules as vectors, so they stay crisp when enlarged for posters or labels. In both cases, scan-test the finished code before printing a large batch.

Why will my QR code not scan?

Common causes are a very small size, weak contrast between modules and background, inverted or unusual colours, glare on a screen and a pattern placed too close to the edge. Increase the size, restore strong contrast, choose a suitable error-correction level and test with a phone.
