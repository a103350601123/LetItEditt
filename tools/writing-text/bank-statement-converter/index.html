In-depth guide

What it actually parses

Each non-empty line is scanned for a date, then for monetary amounts. Numeric and month-name dates are supported, with automatic or manual day/month ordering. Amounts can include currency symbols, thousands separators, negative signs, parentheses and CR/DR markers.

When two or more amounts are found, the first is treated as the transaction amount and the last as the running balance. The description is what remains after dates and amounts are removed.

Balance checking and honesty

Balances are compared in integer cents between adjacent rows where a running balance is present. Rows that do not add up are marked so you can inspect them. A match is never claimed when there is no balance information.

This is a subset of the reference tool. It does not read PDF layouts, run OCR, infer debit and credit columns, repair scanned digits or produce spreadsheet workbooks. Review all output against the original statement before importing it anywhere.

Frequently asked questions

Can it read PDF statements?

Not in this build. The reference application loads PDF.js and Tesseract.js from content delivery networks to extract text and run OCR. Those dependencies are not bundled here, so this tool deliberately accepts text and CSV only.

Are every balance checked?

Only when opening, closing or running balances are present in the text. If no balances are found, the summary says there is nothing to check.

Are my statements uploaded?

No. Parsing happens in your browser and no statement data is sent to a server.

Which formats can I download?

This build exports CSV and QIF. The reference tool also offers XLSX, QuickBooks CSV, Xero CSV and OFX, which are not reproduced here.
