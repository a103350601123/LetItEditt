In-depth guide

What a JavaScript regex tester does

A regular expression is a compact pattern language for finding, validating and replacing text. This tester runs patterns with the JavaScript regular-expression engine in your browser, so the behaviour you see matches what new RegExp() and String.replace() do in web code. That distinction matters: JavaScript regex is not identical to PCRE, Python's re module or Java's Pattern class. Some constructs behave differently and some advanced features are unavailable. Testing here helps you confirm flags, escaping and capture groups before shipping a pattern to production. Paste a representative sample, adjust the pattern, and watch the highlighted matches and match table update. No text or pattern is sent to a server.

How flags change the result

Flags modify how the engine interprets a pattern. Global searches every match instead of stopping at the first one. Ignore case makes letters match regardless of case. Multiline changes the meaning of the start and end anchors so they apply to each line. Dot-all lets a period match line breaks. Unicode enables code-point-aware behaviour and is required for property escapes such as \p{Letter}. The tester shows the effective flags next to the match count, so you can see exactly what is active. If a pattern works in one language but not another, compare the flags first; a missing global flag or an unexpected multiline anchor is a common reason for different results.

Capture groups, indexes and named groups

Parentheses create capture groups. The match table lists each group's value alongside the overall match and its starting index, which makes it easier to debug extraction patterns. Named groups, written as (?<name>...), appear by name instead of by number and are usually easier to maintain. Numbering follows the order of opening parentheses, including nested groups. Non-capturing groups (?:...) group without adding an entry. If a group is optional and did not participate in the match, it is shown as empty rather than as the text undefined. Start indexes refer to the original test string, not to the highlighted preview. Zero-length matches are marked with a symbol because they select a position rather than a span of characters.

Testing replacements before you apply them

When you enter replacement text, the tester runs the same flags through JavaScript's replace operation and shows the result below the match list. Replacement syntax supports $1, $2 and so on for numbered groups, $<name> for named groups, $& for the whole match and $$ for a literal dollar sign. The preview is useful for tasks such as reformatting dates, swapping name order or wrapping values in quotes. It also exposes mistakes quickly: a reference to a group that does not exist stays literal, and an unexpected global flag may replace more text than intended. Review the replacement preview and the match table before copying the output into source code or a data migration script.

Writing patterns that stay readable and safe

Start with the smallest pattern that matches your sample, then add one constraint at a time. Use anchors when the whole string must match, character classes for allowed characters, and explicit escaping for punctuation such as dots and question marks. Test empty input, punctuation, Unicode text and very long strings. Avoid nested quantifiers that can cause catastrophic backtracking on hostile input. In JavaScript, prefer simple string checks when a regex is not necessary, and cap the amount of text you process. Keep patterns in named constants with a comment explaining the intent. This tester highlights matches and caps results at one thousand, but it does not make an unsafe pattern safe in production.

Frequently asked questions

Which regular expression flavour does this tool use?

It uses the JavaScript engine in your browser, the same one used by new RegExp() and String.replace(). Patterns written for PCRE, Python or Java may need changes, especially around named groups, inline flags and some escape sequences.

What does the global flag change?

Without the global flag the tester stops after the first match. With it enabled, every match is highlighted and listed, up to a safety limit of 1,000 results.

Are capture groups shown?

Yes. Numbered and named groups appear in the match table. Optional groups that did not participate are shown as empty, and each match includes its starting index in the original test string.

Does the replacement preview modify my text?

No. The replacement is calculated for preview only. Nothing is changed until you copy the output or apply the pattern in your own code.

Can I use lookbehind or Unicode property escapes?

Lookbehind and property escapes such as \p{Letter} are supported in current browsers but may be unavailable in older ones. Enable the Unicode flag for property escapes. The tester reports an error if the engine cannot compile the pattern.
