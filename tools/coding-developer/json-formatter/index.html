      In-depth guide
      
Why formatting JSON makes debugging easier

      
JSON is deliberately compact. A single API response, configuration export or log entry can arrive as one very long line, which is efficient for machines and miserable for people. A formatter parses that line and prints it again with consistent indentation, line breaks and spacing, so nested objects and arrays become visible at a glance. The data does not change; only its presentation does. That small change makes it much easier to spot a missing field, compare two responses, review a pull request or explain a payload to a colleague. Because the work happens in your browser, you can paste a response while debugging without sending it to a third-party formatting service.

      
What validation checks and what it does not

      
The formatter validates syntax with the browser's built-in JSON parser. That means it enforces the rules of the JSON specification: keys and strings must use double quotes, commas cannot trail the last item, comments are not allowed, and values must be strings, numbers, true, false, null, objects or arrays. When parsing fails, the page shows the parser's error message so you can find the problem instead of guessing. Validation is not a schema check. A document can be valid JSON while containing the wrong field names, missing required values or an unexpected type. Use a schema validator when you need to enforce a contract, and use this formatter to confirm that the document is syntactically sound.

      
Pretty printing versus minifying

      
Pretty printing adds whitespace so humans can read the structure. Minifying removes every optional space, tab and newline so the payload is as small as possible. Both modes produce the same data, and switching between them is a useful way to confirm that formatting has not changed the meaning. Minified JSON is common in API requests, configuration bundles and storage where bytes matter. Formatted JSON is better for documentation, reviews and troubleshooting. Whitespace inside string values is always preserved, so minifying will not alter a message, URL or description. If a value contains meaningful leading or trailing spaces, they remain part of the string after either operation.

      
Choosing indentation and sorting keys

      
You can indent with two spaces, four spaces or a tab. Two spaces are a good default because they keep deeply nested documents narrow enough to read on a laptop. Four spaces are easier to scan when the structure is shallow, while tabs let each editor display the depth it prefers. The optional key-sort control reorders object properties alphabetically and applies the same rule to nested objects. Array order is never changed because arrays often represent sequences where position matters. Sorting is handy for comparing two versions of a configuration file, but avoid it when a downstream system depends on property order. JSON technically treats objects as unordered, yet real code sometimes observes insertion order.

      
A safe everyday workflow

      
Paste the document into the input box and choose Format. If the output is empty and the status turns red, read the parser message and correct the syntax before continuing. Once the structure looks right, use Minify when you need a compact payload, or keep the formatted version for documentation. Copy or download the result only after reviewing it. Remove passwords, tokens, personal data and internal hostnames before sharing a payload, even when processing is local, because the output may still end up in a ticket or chat message. Very large documents can be slow in any browser, so split enormous exports where possible. For a quick conversion of escaped or encoded content, pair this tool with the Base64 encoder or the regex tester.

    

  





  

    

      
Frequently asked questions

      
Is my JSON uploaded to a server?
No. The JSON is parsed and printed by JavaScript running in your browser. This page does not send your input to LetitEdit or to a third-party formatting service.
Does formatting change the data?
Formatting and minifying only change whitespace outside string values, so numbers, booleans and text stay the same. Enabling key sorting does change the order of object properties, but not their values or array order.
Why does the validator reject comments or trailing commas?
Standard JSON does not allow comments or a comma after the final item. The browser parser enforces the JSON specification. JSON5 and JSONC extensions are not accepted unless you remove those features first.
Can it validate against my API schema?
No. This tool checks JSON syntax only. A document can be valid JSON while still having the wrong field names or types. Use a JSON Schema validator when you need to enforce an API contract.
Does key sorting reorder arrays?
No. Arrays keep their original order because position can be meaningful. Sorting is applied recursively to object keys only.
