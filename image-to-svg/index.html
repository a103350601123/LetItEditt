In-depth guide

What this conversion does

An SVG is normally associated with shapes, paths and text that stay sharp at any size. This tool takes a different approach: it places your existing raster picture inside an SVG document as an image element. The pixels are not redrawn or traced; they are carried along unchanged. The result is a single .svg file that browsers can display like any other vector document, with the source width and height recorded in the markup. Understanding that difference matters, because the file is a convenient wrapper rather than a vector version of your artwork, and it will behave like the original photo when scaled. A browser treats that wrapper much like any other SVG file. The markup stays small and easy to inspect.

How the Base64 data URL works

To keep the picture inside one file, the source bytes are encoded as Base64 text and written into the href of an SVG image element using a data URL. Base64 maps binary data to printable characters, which makes it safe to store inside an XML attribute. The browser decodes that text back into the original image when it renders the document. Because the encoding is reversible, the embedded picture is identical to what you opened; no quality is gained or lost in the conversion step. The trade-off is size: the text form is about one third larger than the binary file it represents. The same bytes come out when a browser decodes the attribute. No hidden service performs the encoding for you.

What is inside the exported file

The exported document is small and readable. It contains an opening svg tag with width and height attributes taken from the source image, a viewBox that matches those dimensions, and a single image element whose href holds the data URL. There are no layers, paths, gradients or filters. That simplicity is useful when you want a self-contained asset that can be dropped into HTML, stored in a content system that accepts SVG, or referenced from CSS without a separate image request. You can open the file in a text editor to inspect the metadata, but editing the encoded string by hand is rarely helpful. That makes the file easy to version-control alongside your source code.

Formats and size implications

Open a PNG, JPG or WebP image, check the detected dimensions, and download the generated file. PNG is a good source when transparency matters, because the alpha channel survives inside the embedded data. JPG is smaller for photographs but has no transparency. WebP is compact and widely supported in browsers. In every case the SVG simply carries the bytes you supplied, so its visual quality is exactly the source quality. If you later need a different size, resize the source image first and convert again; editing the width attribute alone only stretches the same pixels. Keep the original image file as well, because it is easier to re-edit. Check that the chosen format supports any transparency you need.

When this approach is useful

A wrapped SVG is handy when a platform accepts SVG uploads but not image files, when you want one self-contained asset with no external references, or when an icon system expects SVG markup. It is also a quick way to include a raster picture in an SVG-based layout without managing a second file. It is not useful when you need to change individual shapes, recolour parts of a drawing, print at billboard size or minimise file size. For those jobs, redraw the artwork with vector tools or run a tracing conversion that produces real paths from the pixel edges. It is also a poor choice when bandwidth matters, since Base64 adds overhead. Think of it as packaging, not artwork conversion.

Limits, privacy and troubleshooting

This conversion does not vector-trace, remove backgrounds, sharpen, compress or alter the picture. Enlarging the SVG reveals the same detail and blur as enlarging the original raster file, so it is not resolution-independent. Encoding is local: the image never leaves your browser, and the downloaded file contains only your data. Some design applications do not render data URLs in SVG image elements; if you see an empty box, open the file in a browser to confirm it is valid, then use a linked image instead for that application. Very large photos create large SVGs and may take a moment to encode. A large photo may also make the markup slow to copy into an editor.

Frequently asked questions

Is my image sent to a server?

No. The file is read in your browser and encoded to a Base64 data URL locally. Nothing is uploaded, and the encoded copy exists only in the current page until you download it.

Can I edit the lines after conversion?

No. The SVG contains an image element pointing to the original raster data, not vector paths. There are no nodes or curves to move, so zooming reveals the same pixels as the source.

Will it stay sharp at any size?

No. Because the pixels are embedded rather than redrawn, enlarging the SVG enlarges the same raster image. For truly resolution-independent artwork, use a tracing tool or redraw the graphic with shapes.

Why is the SVG bigger than the original image?

Base64 expands binary data by about one third, so the embedded copy is larger than the source file. A 1 MB PNG produces an SVG of roughly 1.3 MB before the added markup.

Why does my SVG show a blank box in some apps?

Some older editors do not render data URLs inside image elements. Open the file in a browser first to confirm it is valid. If a tool strips the data URL, link to a separate image file instead, though that loses the single-file convenience.
